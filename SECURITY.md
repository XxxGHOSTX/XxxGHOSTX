## Reporting a Vulnerability

The Thalos Prime ecosystem takes security seriously. If you discover a security
vulnerability, potential data exposure, or other security concern within any Thalos
Prime repository or component, we ask that you report it responsibly.

**Please do not open a public GitHub issue for security vulnerabilities.**
Responsible disclosure protects all users and allows the issue to be addressed
before it can be exploited.

---

## How to Report

Submit your security report **privately and directly** to:

**Tony Ray Macier III**
Email: ltghost047@gmail.com
Subject line: `[SECURITY] Thalos Prime — Vulnerability Report`

### What to Include

Please provide as much of the following information as possible to help us
understand and address the issue quickly:

1. **Affected repository and component** — which repository and module is affected.
2. **Vulnerability type** — e.g., injection, authentication bypass, cryptographic
   weakness, information disclosure, denial of service, etc.
3. **Severity estimate** — your assessment of the impact (critical, high, medium, low).
4. **Reproduction steps** — a clear, step-by-step description of how to reproduce
   the vulnerability, including any required conditions or inputs.
5. **Proof of concept** — a code snippet, script, or test case demonstrating the
   issue, if available (do not include live exploit payloads).
6. **Affected versions** — if you can identify the commit hash, version, or date
   range of affected code.
7. **Suggested fix** — your suggested remediation approach, if you have one.
8. **Your contact information** — so we can reach you with follow-up questions or
   to notify you when the issue is resolved.

---

## Response Process

Upon receiving a valid security report:

1. **Acknowledgement**: We will acknowledge receipt of your report within **5 business days**.
2. **Assessment**: We will assess the severity and validity of the reported vulnerability.
3. **Remediation**: For confirmed vulnerabilities, we will work to develop and test
   a fix. Timeline depends on severity and complexity.
4. **Notification**: We will notify you when the vulnerability has been resolved.
5. **Disclosure**: We request that you do not publicly disclose the vulnerability
   until we have had reasonable time to address it. We aim to coordinate disclosure
   with you where possible.

## Out of Scope

The following are generally out of scope for this security policy:

- Vulnerabilities in third-party dependencies (report these to the upstream maintainer).
- Social engineering, phishing, or attacks targeting individuals.
- Issues in development or testing environments not exposed in production.
- Denial-of-service attacks requiring significant resources.
- Security issues in GitHub's own infrastructure (report to GitHub directly).

---

## Good Faith

We commit to:

- Working with security researchers in good faith.
- Not pursuing legal action against researchers who follow this policy and act in
  good faith.
- Crediting security researchers in our acknowledgements (if they wish to be credited)
  upon resolution of the reported issue.
