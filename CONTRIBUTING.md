## 3. How to Contribute

### 3.1 Reporting Issues

If you have discovered a bug, incorrect behavior, or a documentation issue:

1. Check existing issues to avoid duplicates.
2. Open a GitHub issue with:
   - A clear, descriptive title.
   - Steps to reproduce the issue.
   - Expected behavior vs. actual behavior.
   - Relevant environment details (OS, Python version, etc.).
   - Any relevant logs, error messages, or screenshots.

### 3.2 Security Vulnerabilities

**Do not open a public issue for security vulnerabilities.** Report security issues
privately via the process described in [SECURITY.md](SECURITY.md).

### 3.3 Feature Requests and Suggestions

Feature requests are welcomed but are subject to the sole discretion of the copyright
holder regarding prioritization and implementation. Open a GitHub issue labeled
"enhancement" and describe:

- The problem you are trying to solve.
- Your proposed solution or approach.
- Any alternative approaches you have considered.

### 3.4 Submitting a Pull Request

1. **Complete the CLA** — see [CLA.md](CLA.md).
2. **Fork the repository** and create a feature branch from `main` (or the designated
   development branch).
3. **Follow existing code style** — match the patterns, naming conventions, and
   documentation style used throughout the codebase.
4. **Write or update tests** for any behavior you are adding or changing.
5. **Ensure all tests pass** before submitting.
6. **Write a clear commit message** describing what the change does and why.
7. **Open a pull request** against the target branch with:
   - A descriptive title.
   - A summary of the change and its motivation.
   - Reference to any related issue.
   - Confirmation of CLA acceptance.

## 4. Code Style and Standards

- **Python**: Follow PEP 8. Use type annotations. Docstrings must follow existing
  style in the relevant file.
- **TypeScript/JavaScript**: Follow the existing ESLint configuration.
- **C++**: Follow the existing style in `include/` and `src/`.
- All contributions must pass the project's existing lint, test, and type-check suite.
